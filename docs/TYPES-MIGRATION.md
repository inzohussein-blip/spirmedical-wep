# ترحيل أنواع قاعدة البيانات إلى المخطّط الحيّ

## الحالة

`src/types/database.ts` ما زال **مكتوباً يدوياً**. النسخة المولَّدة من
المخطّط الحيّ محفوظة في `docs/database.generated.ts`.

```bash
npm run db:types   # لإعادة التوليد
```

## ما جُرِّب وفشل — ولماذا

اعتماد الأنواع المولَّدة يُظهر **٧٩ خطأً**، غالبيتها من صنفٍ واحد:
واجهات محلّية داخل الصفحات تُعلن حقولاً غير فارغة، وتُمرَّر إليها صفوف
القاعدة مباشرةً.

جُرِّب إصلاحها آلياً بتوسيع الحقول المُبلَّغ عنها (`T` → `T | null`)
بشكلٍ تكراري. **النتيجة كانت عكسية**:

| الجولة | الأخطاء |
|---|---|
| ١ | ٧٩ |
| ٥ | ١٣١ |
| ١٠ | ١٦٣ |
| ٢٣ | ١٨٦ (توقّف) |

السبب بنيويّ لا تقنيّ: توسيع حقلٍ في واجهة يكسر **كل مستهلكيها** — كل
موضع يعرض ذلك الحقل صار يستقبل `null` بلا حماية. فالتوسيع يدفع الفراغ
إلى الأمام بدل أن يعالجه.

الخلاصة: هذه ليست مهمّة تحويل أنواع، بل **مراجعة سلوك عرض** لكل حقل:
ماذا يجب أن يظهر للمستخدم حين تكون القيمة فارغة؟ والجواب يختلف بين حقل
وآخر (إخفاء الكتلة · شرطة · نصّ بديل · قيمة افتراضية).

## المسار الصحيح

يدوياً، ملفاً ملفاً، بمراجعة كل حقل. النمط المُثبَت في
`src/lib/format/price.ts` هو القدوة: الدالّة تُرجع `null` والمستدعي
يُخفي الكتلة — لا تُطبع قيمة بديلة مضلِّلة.

الترتيب المقترح (الأعلى أثراً أوّلاً):

1. **صفحات القوائم** (`services/*/page.tsx`) — أكثرها ظهوراً للمريض.
2. **صفحات التفاصيل** المتبقّية.
3. **لوحات الإدارة** — أقلّها أثراً (جمهورها داخلي).

## ما أُنجز فعلاً من هذا المسار

٧٨ خطأً أُصلحت في جولةٍ سابقة، وكانت فيها أعطالٌ حقيقية:

| الموضع | الأثر قبل الإصلاح |
|---|---|
| `PriceRow` في عيادات الأسنان | عيادة بحدٍّ سعريّ واحد → `TypeError` يُسقط الصفحة |
| `store.exam_price` في النظّارات | متجر يقدّم فحصاً بلا سعر → الصفحة تسقط |
| `push.ts` ساعات الهدوء | تُقارَن بتوقيت الخادم (UTC) فتُطبَّق ٠٢:٠٠–١٠:٠٠ بغداد |
| تفضيلات الإشعارات | `null` يتسرّب إلى واجهة تتوقّع `boolean` |
