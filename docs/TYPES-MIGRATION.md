# ترحيل أنواع قاعدة البيانات إلى المخطّط الحيّ

## الحالة

`src/types/database.ts` ما زال **مكتوباً يدوياً**. النسخة المولَّدة من
المخطّط الحيّ محفوظة في `docs/database.generated.ts` جاهزةً للاعتماد.

للتوليد من جديد في أي وقت:

```bash
npm run db:types
```

## لماذا لم تُعتمَد بعد

اعتمادها يُظهر **١٥٧ خطأ نوع**، وليست أخطاءً في الأنواع بل ديناً حقيقياً
في معالجة `null`: أعمدة كثيرة تقبل `NULL` في القاعدة بينما تدّعي الأنواع
اليدوية أنّها غير فارغة.

أُصلح منها **٧٨** في هذه الجولة، وكانت فيها أعطالٌ حقيقية لا مجرّد تشدّد:

| الموضع | الأثر قبل الإصلاح |
|---|---|
| `PriceRow` في عيادات الأسنان | عيادة بحدٍّ سعريّ واحد → `TypeError` يُسقط الصفحة |
| `store.exam_price` في النظّارات | متجر يقدّم فحصاً بلا سعر → الصفحة تسقط |
| `push.ts` ساعات الهدوء | تُقارَن بتوقيت الخادم (UTC) فتُطبَّق ٠٢:٠٠–١٠:٠٠ بغداد بدل ٢٣:٠٠–٠٧:٠٠ |
| تفضيلات الإشعارات | `null` يتسرّب إلى واجهة تتوقّع `boolean` |

## المتبقّي (٧٩ خطأ)

غالبيته صنفٌ واحد: **واجهات محلّية مكتوبة يدوياً داخل الصفحات** تُعلن
حقولاً غير فارغة، وتُمرَّر إليها صفوف القاعدة مباشرةً. مثال:

```
Type '{ allergies: string[] | null; … }[]' is not assignable to 'FamilyMember[]'
```

الإصلاح الصحيح توسيع نحو ٥٠ واجهة لتعكس ما تسمح به القاعدة فعلاً — عملٌ
مباشر لكنّه واسع، ويستحقّ جولة مخصّصة بمراجعة كل موضع على حدة بدل تعميمٍ
متسرّع على منصّة طبّية.

## الترتيب المقترح

1. الصفحات التي تعرض أسعاراً أو أعداداً (بقية أعطال `toLocaleString`).
2. صفحات القوائم (`services/*/page.tsx`) — واجهات البطاقات.
3. لوحات الإدارة.
