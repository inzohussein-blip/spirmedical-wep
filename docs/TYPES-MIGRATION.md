# أنواع قاعدة البيانات — الترحيل مكتمل

## الحالة

`src/types/database.ts` **مولَّد من المخطّط الحيّ**. لم يعد مكتوباً يدوياً.

```bash
npm run db:types   # لإعادة التوليد بعد أيّ ترحيل
```

بعد كل ترحيل يغيّر المخطّط، أعِد التوليد وشغّل `npm run type-check`.
انحراف القاعدة عن الملفّات لن يبقى صامتاً بعد اليوم: يظهر خطأَ بناء.

## لماذا استغرق هذا ثلاث محاولات

المحاولة الأولى وسّعت حقول التطبيق آلياً (`T` → `T | null`) فارتفعت
الأخطاء من ٧٩ إلى ١٨٦ — لأنّ توسيع حقلٍ يكسر كل مستهلكيه، فيدفع الفراغ
إلى الأمام بدل معالجته.

الخطأ كان في **اتّجاه** العلاج. الأخطاء الـ٧٧ لم تكن صنفاً واحداً بل ثلاثة:

### أ. خطأ في القاعدة لا في التطبيق (١٦ خطأً)

١٩٨ عموداً بقيمةٍ افتراضية ثابتة (0 · 1 · true · false) تقبل `NULL`.
لا عدّاد «مجهول» ولا علَم «غير معروف» — الواجهات التي تُعلن
`boolean`/`number` كانت **على حقّ**، والمخطّط هو المخطئ.

الترحيل `0020` ثبّتها على `NOT NULL`: **٧٧ → ٦١ بلا لمس سطرٍ واحد في
واجهة عرض.**

### ب. قصور المولّد أمام قيود CHECK (~٢٥ خطأً)

أعمدةٌ كثيرة محروسة بقيد CHECK يحصر قيمها (`status` · `type` · `tier` ·
`severity` · `plan` · `gender` …)، لكنّ مولّد أنواع Supabase **لا يقرأ
قيود CHECK** — الأنواع المُعدّدة (ENUM) وحدها تُترجم إلى اتّحاد — فيُخرج
`string` رغم أنّ القيمة مضمونة.

فالاتّحادات الضيّقة في التطبيق **صحيحة**، والنقص في المولّد.

العلاج تضييقٌ فاحص عند حدّ الصفحة بدل تأكيدٍ أعمى (`as`) يَعِد المُصرِّف
بما لا يفحصه أحد:

* `src/lib/format/vocabulary.ts` — `oneOf` · `oneOfOr` · `jsonObject`
* `src/lib/format/gender.ts` — `toGender`
* `src/lib/specialist-types.ts` — `toSpecialistType`

تحقّقٌ أُجري: قوبلت اتّحادات التطبيق بمفردات القاعدة عموداً عموداً بحثاً
عن عطل «المفردات المفقودة» (صنف الترحيل 0017) — **لم يظهر فرقٌ حقيقي**.

### ج. فراغاتٌ حقيقية تحتاج قرار عرض (~٣٦ خطأً)

هنا وحدها كان الفراغ حقيقياً، والقرار يختلف بين حقل وآخر:

* **قائمة** (`string[] | null`) → `?? []` عند حدّ الصفحة. القائمة الفارغة
  تعني «لا شيء مُدرَج» وهو صادق، و`.includes`/`.join` تنهار على `NULL`.
* **سعر** → لا يُسوّى أبداً. `src/lib/format/price.ts` تُرجع `null`
  والمستدعي يُخفي السطر: لا صفر ولا «غير محدّد» ولا قيمة تخترعها المنصّة.
* **نصّ اختياري** → تُخفى الكتلة.
* **`jsonb`** → يُفحص أنّه كائنٌ فعلاً قبل تمريره (`jsonObject`).

## أعطالٌ حقيقية كشفها الترحيل

الأنواع اليدوية كانت تُخفي هذه كلّها عن `tsc`:

| الموضع | الأثر قبل الإصلاح |
|---|---|
| `OpticalClient` — أسعار الإطارات والعدسات | **بلا أيّ حارس**: متجر بلا سعرٍ لأحد الحدود الأربعة يُسقط قائمة النظّارات كلّها |
| `OpticalClient` — `exam_price` | حارسه `offers_eye_exam` لا السعر |
| `DentalClient` — مدى التنظيف | بلا حارس: عيادة بلا سعرٍ تُسقط قائمة الأسنان |
| `NutritionClient` — `PackageCard` | ثلاثة أسعار فارغة تصل إلى `.toLocaleString` |
| `PhysioClient` · `MentalHealthClient` | كتلة السعر محروسة بالتوفّر لا بالسعر |
| `DoctorsClient` · `DoctorDetailClient` · `DoctorBookingModal` | ثمانية مواضع سعر بلا حارس |
| `appointments.confirmed_at` | **عمودٌ لا وجود له في القاعدة**: خطوة «تأكيد المختص» في الخطّ الزمني بلا وقتٍ أبداً (الترحيل 0021) |

النمط المُتَّبع في الأسعار: يبقى ما يحمل معلومة (التوفّر · زرّ الحجز)
ظاهراً، ويُخفى **السعر وحده** حين لا يكون معروفاً.

## ملاحظة على المخطّط

`users.approval_status` يحمل **قيدَي CHECK** معاً: أحدهما يسمح بـ
`pending/approved/rejected` والآخر يضيف `suspended/expired`. وبما أنّ
كليهما يجب أن يمرّ، فالمفردات الفعلية هي **تقاطعهما** — أي أنّ
`suspended` و`expired` لا يمكن تخزينهما أبداً رغم ما يوحي به القيد الأوسع.

لا أثر عملياً اليوم: الإيقاف مُنفَّذ بعمودٍ منطقيّ منفصل (`is_suspended`)،
ولا موضع في التطبيق يكتب تينك القيمتين. تُركت كما هي عمداً — إسقاط قيدٍ
لا يلزم الترحيل يضيف خطراً بلا مقابل. لكنّها فخٌّ لمن يقرأ القيد الأوسع
ويظنّ القيمتين متاحتين.
